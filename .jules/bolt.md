## 2024-05-24 - Inline Debounce in Functional Components
**Learning:** In this React application, `SearchFromApi` directly called `debounce(callback, 700)` in its function body. Since `debounce` returns a new debounced function every time it is called, a new timer was created on every single render. This meant that if the parent component re-rendered while a user was typing (which is common when updating state on input changes), the previous debounce timeout was lost, causing duplicate and unnecessary API requests because the old timeout wasn't cleared.
**Action:** When using debounced functions inside functional components, *always* wrap the debounced function in a `useRef` (or `useMemo` with an empty dependency array + a ref for the latest callback) to maintain referential equality and preserve the internal timer state across re-renders.
